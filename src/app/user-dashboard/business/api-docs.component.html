Create and follow Shnell deliveries from your own software: the same prices, the same drivers and the same live search as the Shnell app. Keys are created in your Shnell Business dashboard.

Authentication

Send your key on every request:

Authorization: Bearer {{ key }}

Keys never expire. Keep them on your server, never in a website or mobile app: a key can book paid trips. If one leaks, revoke it in the dashboard and create a new one.

How it works
  1. Price the trip (POST /quotes), optional.
  2. Create the order (POST /orders): Shnell starts looking for a driver.
  3. Follow it with a webhook (recommended) or GET /orders/{id}.
Limits
  • 120 requests a minute per key
  • 50 stops per order, 100 open orders at a time
  • JSON in, JSON out, dates in ISO 8601 (UTC), prices in the trip's currency

Webhooks

Set an https URL in the dashboard (API → Webhook). Each time one of your orders changes state, Shnell sends order.<state> (for example order.assigned, order.delivered) with the full order, the same object as GET /orders/{id}. Orders created in the dashboard send events too.

Driver counter-offers. While an order is open, a driver can propose their own price instead of yours. Each new or re-priced offer sends order.offer, and a pulled offer sends order.offer_withdrawn. The event's data is { orderId, currency, listPrice, offer: { driverId, driverName, amount, vehicleType }, order }. Accept it with POST /orders/{id}/offers/{driverId}/accept and {"amount": offer.amount}, or ignore it and keep waiting for a driver at your price. Without a webhook, poll GET /orders/{id}: open offers are listed in offers.

Every stop. When the driver moves a stop, Shnell sends stop.on_the_way, stop.delivered or stop.failed. The event's data is { orderId, stop, order }: stop carries your reference, the cash to collect, deliveredAt, or failReason and failedAt; order is the full order. Each move is sent once, so you can update your own parcel tracking stop by stop, without waiting for the whole trip.

  • Answer with a 2xx within 5 seconds. A failed delivery is retried once.
  • Check the signature with your webhook secret before trusting an event, and ignore events older than 5 minutes.
  • An event can arrive twice: use data.id + data.state (order events) or data.stop.id + data.stop.state (stop events) to skip duplicates.
